## v3.2.2

* Release: This production release consolidates every change since v3.1.1, including the v3.2.0-beta and v3.2.1-beta previews.
* Compatibility: Use AngryEra v3.2.2 or newer on every client that must interpret priority assignments, group layouts, variable families, imported raid-role variables, automatic raid-tank or raid-assistant assignments, or Key=Value boolean metadata. Pages using only features common to v3.1 remain compatible with v3.1.x clients.
* New Feature: Added priority assignments. A variable or `$` marker value written as `Name > Name > Name` resolves to the first listed player who is present and alive, so raid markers and displayed text follow whoever is available. Assignments re-resolve when the group roster or player state changes.
* New Feature: Mouseover marker keybindings now mark a hostile unit under the cursor and fall back to your current target when there is no valid unit. A new Smart Markers setting can relax the restriction to mark any live unit, including friendly players.
* New Feature: Added optional display auto-hide. The assignment fades out when the mouse is away, fades back in over its rendered area, and remains visible for three seconds after the page or displayed content changes.
* Improvement: **Fade in Combat** replaces the old hide-on-combat behavior. When enabled, a visible assignment stays at 10% opacity during combat without changing its manual hidden state; leaving combat restores the exact prior opacity, auto-hide progress, and page-reveal state.
* Improvement: `/ae` is now the canonical slash command throughout AngryEra. `/aa` remains a temporary compatibility alias and prints a local deprecation notice once per login.
* New Feature: Added inheritable raid group layouts. Put a standard `$LAYOUT` on a category, override only the encounter pages that differ, render up to eight named raid subgroups with `{layout}`, and optionally apply the same plan to the live raid.
* New Feature: Layout slots fill from the live roster: a name, a priority list `A > B > C`, a class fill `*MAGE`/`*MAGE x2`, or `group:2`. Auto-fill picks present-and-alive members and never assigns anyone twice.
* New Feature: Added a Group Layout editor on the page right-click menu. Drag members from the roster into the eight raid subgroup boxes, drag between boxes to move or swap them, and right-click a member to take them out. An Edit as text toggle switches the same layout to one group per line.
* New Feature: The Group Layout grid can also be edited by clicking. Click a box title to name that group, so a spore rotation reads as `Spores` instead of Group 3, a member to edit their slot, or an empty row to add one. Layouts can be built solo, before there is a roster to drag from.
* New Feature: A layout slot can hold a `{{Variable}}`, so one name change updates the note and the layout together. Whatever the variable holds is classified afterwards, so it may be a name, a priority list, or a class fill, and an unset one leaves its slot out.
* New Feature: The Group Layout editor now has a Variables column to the right of Unrostered. It lists unused effective inherited string variables and drags their exact `{{KEY}}` tokens into layout slots instead of copying the values they currently resolve to. A used token and any alias currently resolving to the same assigned player disappear until that slot is removed; manual and text-mode edits reject duplicate variable or target assignments too. Numeric variables remain available inside manually written expressions such as `*MAGE x{{Count}}`.
* New Feature: Added composable variable families for reusable ordered role pools. `HEALER*=PRIESTS*,PALADINS*,DRUID*` reads numbered string sources in numeric order, compacts them into ordinary `HEALER1...N` variables for notes and layouts, follows inheritance, can compose other families, allows exact numbered exceptions, and rejects cycles or oversized results.
* New Feature: Edit Variables can take a reviewable snapshot of Blizzard-assigned roles as managed `RAID_TANK1...`, `RAID_HEALER1...`, and `RAID_DPS1...` variables. It does not guess specialization, alter Blizzard roles, or update automatically; re-import after role changes. Saved names remain short unless cross-realm ambiguity requires `Name-Realm`, and the generated roles can feed custom families or layouts.
* New Feature: Added inherited, leader-only `$TANKS` metadata to keep Blizzard's assigned Tank role equal to a comma-separated roster. A nearer page overrides its category, an absent key leaves roles unmanaged, and an explicit empty value clears assigned Tanks without changing Healer or Damage roles.
* New Feature: Added inherited, leader-only `$ASSISTS` metadata for actual raid-assistant rank. When present, AngryEra disables Everyone Is Assistant and reconciles the exact comma-separated list by promoting missing assistants and demoting extras; an explicit empty value clears the list.
* Improvement: Raid-tank and raid-assistant automation accepts unique short names or `Name-Realm`, allows the same non-leader player in both lists, stays silent when no change is needed, supersedes unissued work with the latest exact display, and rechecks any already-issued change before continuing.
* Improvement: Missing-roster warnings from automatic layouts and `$TANKS`/`$ASSISTS` setup now print once for the current raid instead of repeating while pages are cycled or the roster is assembled. Explicit Apply attempts and operational failures still report every result, and joining a later raid starts a fresh warning cycle.
* Improvement: Tank-role reconciliation now matches Classic's live enum values, recognizes its numeric no-role value, requires Blizzard's documented boolean acceptance, falls back to the string API when an enum wrapper errors, validates hard class-role limits before making any raid-assignment change, and exposes compact `/ae debug` role-call results.
* Clarification: `$TANKS` assigns Blizzard's ordinary Tank role for role icons and sorting. The protected Main Tank flag that populates the dedicated Tank raid-frame row requires a secure player action and is not changed by automatic page updates.
* Fix: Raid-role automation now fails closed on incomplete inherited variables or unavailable Blizzard state, waits for transient roster settlement, paces synchronous role events, and invalidates old-page work as soon as a newer display starts transferring.
* Fix: Qualified-assistant edit proposals cannot change the effective privileged `$TANKS` or `$ASSISTS` metadata that the raid leader applies.
* Improvement: An accepted assistant edit that makes no effective change no longer republishes the full page, avoiding unnecessary raid traffic while still returning the correlated result.
* New Feature: Categories have a Group Layout too, edited the same way from their right-click menu. A category holds the raid's standard arrangement and every page under it inherits that, so only the fights that move people — spore rotations, resist groups — need a layout of their own. The category record stays local; its effective variables and layout travel with a displayed descendant page as rendering context.
* New Feature: The raid leader or a qualified raid assistant can manually apply a validated layout to the raid, moving members into the subgroups it lays out. In combat, the exact displayed page is queued until combat ends. Raid assist alone does not grant the action by default; officer qualification also requires the current raid leader to be in that officer's guild, while local trusted-assistant and allow-all settings remain explicit overrides.
* New Feature: Added inherited `$AUTOAPPLYLAYOUT` metadata for leader-only display transitions. After AngryEra records its initial display state, moving from no page or another page to a different destination page can apply that page's effective layout. Set `$AUTOAPPLYLAYOUT=$true` on a category, use `$AUTOAPPLYLAYOUT=$false` for descendant exceptions, and retain the same validation and combat queue; qualified raid assistants remain manual-only.
* New Feature: The Group Layout editor now has an explicit **Inherit layout** checkbox. The nearest ancestor layout remains visible but read-only; saving while checked removes the local override and resumes that default, while unchecking creates an editable custom copy.
* Improvement: Imported roles, custom families, inherited layouts, `$AUTOAPPLYLAYOUT`, `$TANKS`, and `$ASSISTS` can form one reusable raid template: refresh or reorder the source lists once, and descendant notes, layouts, raid roles, and permissions keep the same stable assignments unless a page declares an exception.
* Behavior Change: Key=Value booleans now use exact `$true` and `$false` literals. Unprefixed `true`/`false` in any capitalization are ordinary strings so players named True or False work in assignments, families, layouts, and marker targets. JSON retains native booleans; legacy unprefixed automation flags are no longer enabled.
* Improvement: Applying an already-satisfied raid layout now stays silent instead of repeatedly announcing zero moves; actual moves, combat queues, and errors still report normally.
* New Feature: Encoded AA export and import now have default-on variables-and-metadata options. Complete exports preserve raw Key=Value or JSON variables, families, assigned-role snapshots, layouts, markers, and automation metadata at every included hierarchy level; content-only exports and imports omit them without erasing an overwritten root page or category's existing setup. Complete exports retain earlier AA Encoding compatibility, while older clients safely reject the new content-only format.
* New Feature: Pages and categories can be pinned or unpinned from their right-click menus. A pinned category protects received pages throughout its subtree, and every pin remains local to that installation.
* New Feature: Added a confirmed **Menu > Wipe Unpinned** action for clearing the local page library. It removes every unpinned page and category regardless of ownership, keeps pinned pages and complete pinned-category subtrees, and safely rehomes a kept pin when an unpinned ancestor is removed.
* Improvement: The first upgrade automatically pins topmost locally owned categories when no live pins already exist. Existing prerelease pin choices are preserved, and `/ae migratepins` safely re-runs the additive step without removing any pins.
* Improvement: The page tree now marks pins with a persistent gold favorite-star icon and orders each sibling level as pinned categories, pinned pages, a divider, then unpinned items in their existing manual order. Nested pages stay in their categories, and raid navigation order is unchanged.
* New Feature: Added optional cleanup of pages received from others. A Page Library setting removes them automatically at login, and a Clean Received Pages button removes them on demand. Pinned pages, descendants of pinned categories, and the current display are always kept; pages you created or imported are never removed.
* Fix: Layout application now fails before moving anyone when a name is missing or ambiguous, a player appears twice, or a variable, class, or roster expansion would overfill a subgroup.
* Fix: A combat-queued layout is bound to the exact displayed page, revision, and inherited context. Changing any of them cancels the request; when combat ends, AngryEra recomputes the plan from the live roster, rechecks permission, and applies it once.
* Fix: Raid layouts now move one identity at a time, wait for Classic to acknowledge each change, and resolve fresh raid indices before continuing, preventing roster renumbering and API throttling from targeting the wrong player.
* Improvement: Full-raid layout application now prioritizes reciprocal swaps and the shortest available subgroup cycles before using unbound fillers. Complete 40-player raids stay within the five-player subgroup cap while requiring substantially fewer protected raid calls for large rearrangements.
* Fix: Group Layout editing preserves JSON-form variables, merges into the latest saved variable state, and never applies an older layout while an assistant proposal is pending.
* Fix: Group Layout editing uses the exact authoritative inheritance context for an actively displayed received page, and saving or applying an unchanged inherited layout no longer creates a page override.
* Fix: Escape and the close button now dismiss only the Group Layout or Edit Variables child editor, keep the main AngryEra window open, and ask before discarding an unsaved layout, inheritance choice, or variable draft.
* Fix: The editor applies only the exact displayed page, while category layouts direct the user to display an inheriting page; `/ae applylayout` consistently uses the actively displayed page.
* Fix: Saved raid templates now round-trip category and page variables, including category layouts and page-specific overrides, without publishing a newly loaded page before its variables are present.
* Fix: Short player names are now accepted only when unique across the current group; priority assignments, automatic markers, and raid layouts no longer guess the local-realm player when another realm has the same name.
* Fix: JSON-backed variable edits preserve the distinction between empty objects and empty arrays when managed metadata is inserted or updated.
* Fix: The Group Layout window is now fixed to show all eight subgroup boxes without outer vertical scrolling; the Unrostered and Variables palettes scroll independently when either exceeds its available column.
* Improvement: The Group Layout editor now uses native-style five-slot subgroup rows, centered subgroup labels, clearer drag previews and continuous drop highlights, and modal group-name prompts that keep the parent editor inactive until dismissed.
* Improvement: Edit Variables and Group Layout now use matching action footers: Cancel and Save/Close align at the right, Apply remains at the left, and the resizable variable editor keeps its actions clear of the resize grip. Their primary action reads Close while the draft is clean, changes to Save after an edit, and stays open as Close after a successful save.
* Improvement: Group Layout preserves slot order in the editor and rendered note. Apply guarantees subgroup membership, but does not force physical row order because Blizzard exposes no direct safe within-subgroup position operation.
* Fix: Edit Variables no longer shadows Lua's `type()` function while saving, and a stale dialog cannot report success, write through a deleted/replaced/newly read-only page or category, or overwrite a newer variable edit.
* Fix: Received-page cleanup now fails closed when ownership metadata is missing or corrupt, and repaired identity counters no longer reuse pruned page identifiers.
* Fix: Startup now sanitizes corrupt saved settings and window/display state, repairs invalid hierarchy links and cycles, and rehomes affected pages or categories instead of allowing malformed data to break the editor.
* Fix: Oversized or invalid local edits and imports are rejected before AngryEra allocates identifiers, mutates the page library, or publishes a change.
* Fix: Version checks and display recovery no longer repeat redundant requests, stale group-session work is discarded, and long-running request tracking remains bounded through roster and leadership changes.
* Fix: Disabling and re-enabling AngryEra now tears down pending work and auxiliary editors cleanly, closes import/export windows, and reuses the existing assignment display instead of leaking UI state.
* Packaging: Corrected package-metadata YAML and Markdown changelog handling, normalized embedded-library path case, restored the canonical `Bindings.xml` filename, made the root embed manifest valid XML, pinned Git externals to tested commits, and added the project's BSD 3-Clause license.

## v3.1.1

* **BREAKING CHANGE**: Rebuilt shared assignments for the current group. This release cannot share assignments or displayed pages with earlier AngryEra or AngryAssignments versions. Everyone who participates in shared assignments must update before the raid.
* **BREAKING CHANGE**: The current party or raid leader is now the only player who can select or clear the shared display. AngryEra shares the active page and the variable context needed to render it instead of mirroring entire page libraries through the guild.
* Improvement: Existing pages, categories, settings, and legacy permission choices migrate automatically. Downgrading after opening this release requires restoring a pre-upgrade SavedVariables backup.
* New Feature: Added inherited variables across nested categories. Values merge from the outermost category through nested categories to the page, with the nearest value winning.
* New Feature: Added inherited `$` metadata for assignment automation and addon integrations.
* New Feature: Added automatic raid-marker assignments using `$STAR`, `$CIRCLE`, `$DIAMOND`, `$TRIANGLE`, `$MOON`, `$SQUARE`, `$X`/`$CROSS`, and `$SKULL` page metadata.
* New Feature: Added boss-kill auto-advance with `$AUTOADVANCE`, `$ENCOUNTER`, and `$ENCOUNTERID`. Only the leader advances after a successful kill, and sequences use locally owned sibling pages inside one category.
* New Feature: Added `ANGRYERA_NOTE_UPDATE` and public getters for the displayed note, resolved variables, metadata, and hierarchy for WeakAuras and other addons.
* New Feature: Added session-only `/aa debug`, `/aa debug on`, `/aa debug off`, and `/aa debug status` diagnostics.
* New Feature: Added **Leader + Qualified Assistants**, **Leader Only**, and **Ignore Shared Changes** receive policies, plus **Trusted Assistants** and **Allow All Raid Assistants** controls.
* New Feature: Qualified raid assistants can propose name, variable, and content edits to the exact active shared page. They must currently have raid assist and also be a guild officer or higher in the leader's guild, be listed as trusted, or be covered by **Allow All Raid Assistants**.
* Improvement: The leader serializes accepted assistant edits and publishes the final page. Conflicting or superseded assistant work remains visible as a recoverable draft instead of being silently discarded.
* Improvement: Page changes are faster and ordered. Rapid Previous/Next navigation settles on the final selection, and an older delayed update cannot replace the newest page.
* Improvement: Late joiners, reloaded clients, dropped display responses, and raid-leader changes automatically recover the leader's current page.
* Improvement: Received-page revisions preserve each player's local category placement and ordering. Replacing read-only received data during import creates a uniquely named local copy.
* Improvement: Restore loads an older content version as an unsaved draft; the page changes only after **Save**.
* Improvement: Version checks now focus on the current party or raid and report same or different versions, clients not accepting shared changes, and clients without the addon. The current leader and raid assistants can run the check, while automatic version discovery stays leader-driven.
* Improvement: Strengthened validation and size limits for encoded imports and shared data, including tighter decompression bounds for data received on the general sharing channel.
* Fix: Stopped unnecessary idle sharing requests and stale responses that could cause repeated background traffic.
* Fix: Prevented page jumping, stale leader state, and updates from a former leader after group leadership changes.
* Fix: Hardened automatic marker cleanup so AngryEra does not fight manual marker changes.
* Fix: Hardened auto-advance against wipes, ambiguous encounter bindings, missing next pages, and temporary send failures.
* Fix: Removed the invalid `PARTY_CONVERTED_TO_RAID` event registration that caused an error on Classic clients.
* Fix: Saving a shared page that has no effective changes no longer reports a false page-update conflict.
* Fix: Corrupt or hand-edited saved data no longer prevents the addon from loading. Invalid page or category records are dropped with a notice so migration and synchronization still start.
* Fix: A malformed trusted-publisher setting is ignored safely instead of silently rejecting every assistant edit.
* Fix: Retained bookkeeping for deleted local pages and categories is now bounded, so saved data does not grow without limit for players who create and remove many templates.
* Fix: Guild roster updates refresh the display through a cancelable timer that stops cleanly when the addon is disabled.
* Developer: Added broad regression coverage for permissions, leader handoffs, active-page delivery, variables, metadata, automatic markers, auto-advance, imports, migrations, and the public API.
* Developer: Auto-advance reports its decisions, including why a kill did not advance, through `/aa debug`.
* Developer: Corrected the protocol-3 synchronization contract notes, removed unused permission helpers, and restored formatter conformance.
